# 定制视频平台 — 功能设计书 v1.1

> 状态：草稿，待讨论确认（v1.1：确认冷启动策略、品类结构、目标市场等关键决策）
> 目的：明确平台的功能范围、用户角色、核心流程与数据结构，作为后续原型设计和技术选型的依据。

---

## 1. 项目概述

### 1.1 一句话定位
一个面向"个人重要时刻"（生日为主）的定制化视频内容平台。业务不局限于"重要时刻"这一单一场景——同一套内容生成能力也用于自运营的 YouTube 睡前故事频道，作为流量入口和获客渠道。用户提交素材和需求，平台对接内容生成能力产出定制视频。

### 1.2 核心价值主张
- 对**下单用户**：几分钟内完成一次"轻定制"，获得有情感冲击力、专属感强的内容，而不需要自己会剪辑、会找资源。
- 对**平台**：把"内容生成"这个环节抽象为可插拔的能力（不管是 AI 生成、人工制作、还是外包团队），平台的核心资产是**流量入口 + 用户数据 + 履约流程**，不锁死在某一种生成技术上。同一套引擎既服务"付费定制订单"，也服务"YouTube 免费内容"，两者共用模板库和生成对接层。

### 1.3 业务范围（本期 vs 二期）
| 范围 | 本期（V1，冷启动阶段） | 二期（预留接口，不深入设计） |
|---|---|---|
| 核心业务 | 定制视频下单、生成对接、交付 | — |
| 细分品类 | 幼儿向（0-4岁）、儿童向（4-12岁，含卡通/风格化形象模板）、成人趣味向、宠物向（现在就做，庆生场景） | 宠物向扩展为独立 YouTube 内容线 |
| 内容分发 | YouTube 频道自运营（睡前故事内容，用本期生成能力产出，冷启动期即可同步做） | 频道内容管理后台、批量排期发布 |
| 增值服务 | — | 摄影师预约 |
| 商业模式 | 单次付费下单、朋友免费试用（冷启动） | 会员订阅、素材库复用、B端批量定制 |

> 说明：宠物向从"未来扩展"提前到本期——先做"宠物庆生"这个和现有下单流程一致的场景；宠物向的独立 YouTube 内容（不依赖下单，纯内容运营）放二期，等验证了内容生成能力和内容质量后再规模化产出。

## 2. 用户角色

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| **终端用户（下单人）** | 家长、成年子女、朋友（个人用户为主，本期不考虑B端） | 快速、低门槛地做出一个让当事人惊喜/感动的视频 |
| **视频接收方（被祝福人）** | 小孩、宠物、朋友本人 | 被动方，不直接使用平台，但是内容设计的核心对象 |
| **内容生产方 / 生成能力提供方** | 无论是AI服务商还是签约的人工创作团队 | 通过标准化接口接单、交付 |
| **平台运营/客服** | 内部人员（冷启动期可能就是你自己） | 处理异常订单、内容审核、纠纷处理 |
| **平台管理员** | 内部人员 | 后台管理：定价、模板上下架、供应商管理、数据看板 |
| **摄影师（服务提供方，二期）** | 平台签约或众包的自由摄影师 | 接单、赚钱、评价积累 |

**冷启动获客策略（供本期功能设计参考）**：先在本地母婴群推广，邀请身边朋友免费试用；核心获客/收集需求的入口是网站上一份**简单、有条理的调查问卷**，替代传统的多步骤下单表单，既降低用户填写门槛，也方便你自己收集足够的信息来人工/半人工制作视频。这意味着本期的"下单表单"（模块 B2）应优先按"问卷"体验设计，而不是电商式的层层选购流程。

## 3. 核心业务流程（主干流程）

```
用户登录（一键社交登录：Google / Apple / Facebook 等，尽量减少注册步骤）
    ↓
选择视频类型（幼儿向0-4岁 / 儿童向4-12岁 / 成人趣味 / 宠物向）
    ↓
选择或搜索"内容模板"（风格、时长、场景）
    ↓
填写定制信息问卷（简单、有条理，见第5节数据模型）
    ↓
（可选）上传素材：照片、语音、文字祝福语
    ↓
下单支付（冷启动期：朋友/母婴群用户可走"免费试用"路径，跳过支付）
    ↓
系统生成"生成任务"，对接内容生成能力（黑盒，按第6节接口规范）
    ↓
内容合规审核（自动+人工）
    ↓
生成结果反馈给用户（预览）
    ↓
用户确认 / 提出一次修改 → 满意后正式交付
    ↓
订单完成 → 邀请评价 → 售后/复购触达
```

> 摄影师预约（到场拍摄）作为二期功能，不在本期主流程中体现，详见模块 C 说明。

## 4. 功能模块划分

### 模块 A — 用户账户体系
- **登录方式（尽量简化，降低冷启动期的使用门槛）**：优先接入社交登录（Google、Apple ID、Facebook），符合海外华人用户的使用习惯；国内用户可后续再补充微信登录。不建议本期做独立的手机号/邮箱注册+密码体系，减少开发和用户的双重负担。
- 用户主页：我的订单、我的视频（可回看下载/分享）、收藏的模板
- 档案管理：允许用户保存多个"被祝福对象档案"（孩子、宠物等，含姓名、生日/年龄、偏好），下次下单直接复用，省去重复填表

### 模块 B — 视频定制核心流程
这是整个产品的心脏，建议做成**统一的下单引擎 + 差异化的表单配置**，而不是三套独立系统。

#### B1. 品类与模板库
- 品类（Category），按年龄段+场景划分：
  - **幼儿向（0-4岁）**：可爱卡通形象为主，语言/情节都更简单
  - **儿童向（4-12岁）**：可包含风格化的英雄/冒险/搞笑类形象模板（原创风格化，不直接使用受版权保护的角色名称和形象，见 B1 说明与第7节风险提示）
  - **成人趣味向**：真人表演类（如多语言唱跳祝福）
  - **宠物向**：宠物庆生场景，本期就做
- 每个品类下挂多个"模板"（Template），模板定义：
  - 风格预览（示例视频/封面图）
  - 适用场合标签（生日、满月、升学、纪念日、宠物领养纪念日……）
  - 所需素材类型（是否需要照片、是否需要孩子声音、是否需要祝福语文本）
  - 价格、交付时长（如"24小时内交付" vs "3天精修版"）
  - **时长选项**：不做过长内容，分两档即可——
    - 短视频档（数十秒，适合快速分享，如生日祝福）
    - 中等长度档（几分钟，适合睡前故事等需要情节铺陈的内容）

#### B2. 定制信息表单（按品类动态渲染）
公共字段：
- 被祝福人姓名、年龄/生日、称呼（昵称）
- 使用场合（生日会/家庭聚会/线上分享等）
- 祝福语文本（用户自己写 或 选择平台提供的模板文案再微调）
- 特殊要求备注（自由文本）

品类差异字段：
- **幼儿向（0-4岁）**：喜欢的颜色/动物/卡通风格、是否需要睡前故事情节、故事主题偏好
- **儿童向（4-12岁）**：偏好的角色风格（英雄类/冒险类/搞笑类，用"风格标签"选择，不直接指定受版权保护的角色名）
- **成人趣味向**：表演风格（唱跳/喊话/整蛊）、语言（中文/方言）、按被祝福人年龄进行内容分级（见第7节风险提示）、是否需要提及具体梗/称呼、尺度自查（是否涉及公司同事等需要避免过界的内容）
- **宠物向**：宠物类型（猫/狗等）、宠物名字、宠物性格/特征描述、庆祝场合（生日/领养纪念日）

素材上传：
- 照片（用于形象参考或换脸类效果，需明确肖像授权勾选）
- 语音（如需要孩子/用户声音克隆，需要单独的授权确认）

#### B3. 订单与支付
- 冷启动期：支持"免费试用"下单路径（跳过支付，用于母婴群/朋友推广）
- 购物车/直接下单
- 优惠券、拼团、储值卡（预留）
- **支付方式（面向北美+海外华人市场为主，兼顾国内用户）**：优先接入 Stripe（覆盖信用卡、Apple Pay、Google Pay），同时支持微信支付/支付宝（服务国内或习惯用这两种方式的华人用户）
- 订单状态机：待支付/免费试用确认 → 待生成 → 生成中 → 待审核 → 待用户确认 → 已交付 → 已完成 / 售后中 / 已取消

#### B4. 生成任务对接层（关键抽象层）
> 本期设计书**不涉及具体生成技术**，但要定义好平台与"生成能力"之间的接口契约，方便未来替换/并行接入多家供应商（AI模型、外包团队、混合模式都可以）。

- 平台把一个订单转成一个标准化的「生成任务」JSON，推送给生成侧
- 生成任务须包含：模板ID、素材（图片/音频URL）、文本内容、时长要求、风格参数、优先级/SLA
- 生成侧回调：进度更新、预览稿、最终成片、失败原因
- 支持"人工兜底"：如果自动生成失败或效果不佳，可以将任务转人工团队处理，走同一套任务接口，保证用户侧体验一致

#### B5. 内容审核模块（重要，不能省）
- **合规审核**：是否涉及版权角色、敏感词、露骨/低俗内容（尤其成人趣味类涉及真人表演，风险更高）
- **儿童安全审核**：涉及儿童的内容需额外严格把关（肖像、隐私信息不外泄、内容适龄）
- 审核方式：自动审核（关键词/图像识别）+ 人工抽检/全检（视业务量而定，初期建议全检）
- 未通过审核的订单：自动退款或转人工客服跟进

#### B6. 交付与售后
- 视频预览 → 用户确认或申请一次免费修改（限定修改范围，比如文案微调，不含重新生成整个风格）
- 最终成片支持下载、生成分享链接、一键分享到微信/朋友圈
- 售后：不满意退款规则、超时未生成的补偿机制

### 模块 C — 摄影师预约模块（二期，本期只占位不实现）
本期不做功能设计和开发，仅在架构上预留：数据模型里保留 Photographer / Booking 实体（见第5节），以及"是否含摄影服务"这个订单字段，方便二期直接接入而不用改动核心订单结构。等核心视频定制业务跑通、验证了需求后，再展开摄影师端（入驻审核、接单、结算）、用户端（搜索预约、沟通）、平台侧（撮合、佣金、纠纷仲裁）的详细设计，以及与视频订单的联动/耦合方式（独立下单 vs 视频订单的附加服务，见第8节）。

### 模块 D — 内容库/模板管理后台（运营侧）
- 模板上传、上下架、定价管理
- 素材/风格标签体系维护
- 数据看板：品类销量、复购率、客单价、审核拒绝率、生成成功率/耗时

### 模块 E — 客服与工单系统
- 用户发起售后/投诉 → 工单分配 → 处理 → 关闭
- 常见问题：生成效果不满意、超时未交付、摄影师爽约、内容审核被拒申诉

### 模块 F（二期，预留不深入设计）
- YouTube 频道内容管理后台（把平台生成的睡前故事类内容批量导出、排期发布——本期可以先手动搬运，量大了再建后台）
- 宠物向独立 YouTube 内容线（不依赖下单流程的纯内容运营，本期的"宠物庆生"下单场景验证效果后再规模化）
- 摄影师预约模块（同模块C说明）

## 5. 核心数据模型（概念级，非数据库设计）

- **User**：用户ID、联系方式、地址、账户余额/优惠券
- **ChildProfile / SubjectProfile**（被祝福人档案，不限于儿童）：姓名、年龄/生日、关系、偏好标签、历史使用记录
- **Category**：品类（幼儿向0-4岁/儿童向4-12岁/成人趣味/宠物向…）
- **Template**：所属品类、风格素材、所需字段配置、价格、时长选项
- **Order**：用户ID、模板ID、被祝福人档案ID、表单数据快照、状态、金额、是否含摄影服务
- **GenerationTask**：关联订单、素材URL集合、生成参数、状态、供应商标识、回调结果
- **ReviewRecord**：关联订单、审核类型、审核结果、审核人/规则、备注
- **Photographer**：基础信息、资质、地区、档期、评分
- **Booking**：关联用户、摄影师、时间地点、状态、价格
- **Ticket**：客服工单，关联订单，处理记录

## 6. 非功能性需求

- **隐私与合规**：涉及儿童信息、人脸、声音等敏感数据，需要明确的用户授权勾选、数据留存期限、删除请求处理流程（尤其如果未来面向有 COPPA/《未成年人网络保护条例》等要求的市场）。
- **内容合规**：见第4节 B5，需要独立的审核流程，不能只靠事后投诉处理。
- **弹性对接能力**：生成任务接口要与具体技术方案解耦，方便你未来更换或并行多个生成供应商，也方便"人工兜底"。
- **SLA 管理**：不同模板可能对应不同交付时效承诺，需要在下单前明确告知用户，并有超时预警机制。
- **可扩展的品类体系**：宠物、以及未来可能出现的其它场景（毕业、求婚、节日祝福等）应该都能直接复用模块B的引擎，只需新增"品类+模板"配置，无需重新开发。

## 7. 风险与建议（供你决策参考）

1. **版权风险**：已确认走"原创风格化替代"路线，不做正规IP授权。这个方向本身没问题（大量同类产品都是这么做的），但需要注意：风格化程度要足够，不能只是把角色名字换掉、形象还是高度神似（比如配色、招牌动作、专属道具都照搬），这种"擦边"做法法律上仍可能被认定侵权，尤其一旦被权利方盯上、规模做大后被投诉的概率会显著上升。建议内容审核规则（模块B5）里明确纳入"形象相似度"这一项检查标准，而不只是查名字关键词。
2. **成人趣味类内容的合规边界**：已确认按被祝福人年龄分级、且需符合法律法规。除了年龄分级，仍建议关注：涉及真人表演、可能涉及种族相关的内容形式，要避免物化或刻板印象化某个群体，也要避免被用于骚扰、恶搞第三人的场景——可以在下单问卷里加一条"被祝福人是否知情同意"的软性提示，并保留内容审核的一票否决权。
3. **儿童数据与肖像授权**：凡涉及儿童照片/声音的上传，必须有清晰的监护人授权确认流程。由于目标市场包含北美，**儿童数据的收集和处理需要符合 COPPA（美国《儿童在线隐私保护法》）**的相关要求（比如收集13岁以下儿童信息前的可验证家长同意机制），建议在B2表单设计和账户体系里从一开始就把这条纳入，而不是后补。
4. **生成能力的不确定性**：由于生成环节本期不深入设计，建议在B4模块预留"人工兜底"路径，避免因技术方案不成熟导致用户体验断档——冷启动期你自己/小团队人工介入制作也是一种"人工兜底"，接口层面提前按这个思路设计即可。

## 8. 关键决策记录

| 问题 | 结论 | 对设计的影响 |
|---|---|---|
| IP风格路线 | 原创风格化替代，不做正规授权 | 模板库不使用受版权保护的角色名/形象；内容审核需加"形象相似度"检查（见第7节） |
| 成人趣味类内容边界 | 按被祝福人年龄分级，需符合法律法规 | B2表单需要年龄分级字段；B5审核规则按分级设置不同尺度 |
| 摄影师预约功能定位（独立业务 vs 视频订单增值服务） | 二期再设计，本期不展开 | 模块C本期只占位，数据模型预留 Photographer/Booking 实体 |
| 目标市场 | 中国大陆 + 海外华人市场（用户本人在北美） | 登录方式以社交登录为主；支付接入 Stripe 为主、微信支付宝为辅；儿童数据需符合 COPPA |
